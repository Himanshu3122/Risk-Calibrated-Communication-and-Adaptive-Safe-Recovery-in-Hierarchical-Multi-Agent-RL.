# Implementation Assumptions

The manuscript (`main.tex`) specifies the architecture, equations, environment geometry, fault taxonomy, hyperparameters, and protocol, but leaves many implementation details open. Each assumption below records what was missing, what this repository does, why, and where to change it. Code comments cite these IDs.

Classification follows the build instructions: **B** = reasonable engineering inference needed to run, **C** = approximation of something the paper describes but underspecifies, **D** = not implementable from the available material.

| ID | Class | Missing in paper | Decision | Why reasonable | Change it in |
|---|---|---|---|---|---|
| A1 | C | Fire-spread constants and map generator distributions (fuel, terrain, wind, ignitions) | Alexandridis-style CA: `p = base_spread·(0.5+fuel)·exp(0.5V)·exp(V(cosθ−1))·exp(1.5Δelev)·src_intensity`, diagonal ×0.7; smoothed random fuel with ~18% non-burnable rock; wind direction uniform, speed U(0, 1); burning cells intensify by 0.15/step and burn out after 6 steps; new ignitions start at 0.6 | Keeps the structure of the cited CA model (fuel, wind, slope, source) with bounded probabilities | `envs/hierfire.py`, `EnvConfig` |
| A2 | B | Exact crew action set ("movement, direct suppression, firebreak construction, and resource requests") | 8 discrete actions: stay, N, S, E, W, suppress (−0.5 intensity on own + 4-neighbors), firebreak (fuel→0 on own cell), request (sets report bit 13) | Direct reading of the listed action types | `envs/hierfire.py` |
| A3 | C | Where drops land, when, and how crews learn about them | Coordinator allocates drops per region; each drop hits the hottest burning cell of that region (3×3 extinguish, fuel ×0.3) `drop_latency=2` steps later. Region r knows the targets only if **its own** newest downlink goal message refers to that decision (fixed in revision: targets were previously pooled across regions) | Without latency a crew could never react to a drop. Coupling target knowledge to the faulty downlink makes communication failures safety-relevant | `EnvConfig.drop_latency`, `RiCoRSystem._known_targets`, `_drop_masks` |
| A4 | B | Whether entrapment is counted per step or per event | Safety cost = entrapment **onsets** per crew (transition from safe to unsafe) + one event per crew within `drop_radius` of a landing drop. Standing in a burning cell also counts as unsafe | Per-step counting over 400 steps would dwarf the budget d = 0.5. Onset counting matches "events" in Sec. VI-A | `HierFireEnv.step` |
| A5 | B | Content of the "16-dimensional regional reports" | burning share, mean intensity, max spread prob., front centroid (2), threatened-asset share, remaining asset value, 3 crew positions (6), request flag, wind (2) | All are locally observable and decision-relevant for allocation | `HierFireEnv.reports` |
| A6 | C | Network architectures beyond Table III widths | MLP encoders; one regional policy shared by all regions (with region one-hot); coordinator scores one gated slot per regional report; policies are feed-forward (no recurrent history) | Parameter sharing is standard in MAPPO. Per-region slots are needed because allocation is per region. The paper gives no recurrent policy | `models.py` |
| A7 | C | Loss weights c_val, c_c, c_r (manuscript HR-06) | 0.5, 0.5, 1.0 | Conventional PPO defaults | `TrainConfig.value_coef/cost_coef/reliability_coef` |
| A8 | C | Gilbert–Elliott parameters beyond mean burst 14 | Stationary bad-state fraction 0.25 (p_gb = 0.25·p_bg/0.75), full loss in the bad state | Gives bursty loss of similar average severity to F1 | `comm/faults.py::_ge` |
| A9 | C | How the F6 adversary "maximizes coordinator misallocation" | Heuristic: compromised senders push threat fields (burning share, intensity, max spread, threatened assets) toward the opposite extreme by ε (ℓ∞-bounded) | Inverts the allocation signal within the stated budget. A learned adversary is not specified | `Channel.mislead` |
| A10 | C | Share of messages affected by F4/F5; U1 "unseen rates"; U2 relay effect; training ranges | F4: 50% of messages, 30% of fields, σ = 0.5. F5: 50% of messages. U1: GE bad fraction 0.35 with burst 20, corruption 60% at σ = 0.8, ε = 0.5. U2: relayed uplinks get +U[1,3] steps delay and 0.15 extra loss. Training ranges in `sample_training_spec` | Within or just outside the training ranges, as the held-out design requires | `comm/faults.py` |
| A11 | C | Form of the distributional cost critics and of the tail term for a factored crew action | Quantile critics (16 quantiles) fitted to **discounted** cost-to-go (revision; previously undiscounted). Regional tail = Σ_crews E_{a~π_c(·\|M; w0)} CVaR_α Q^c(x_c, a) (revision; previously Σ max_a). Coordinator tail = CVaR_α of a **coordinator-local** critic Q^c_0(gated reports, w, valid, mode, allocation, t), evaluated at the expected allocation shares at decision steps (revision; previously a critic on the true global state) | Sum of per-crew CVaRs upper-bounds the CVaR of the sum (subadditivity). Receiver-local inputs keep execution decentralized | `models.QuantileCritic`, `RiCoRSystem._sensitivity`, `RiCoRSystem.coord_local`, `Trainer._ppo_losses` |
| A12 | C | Verification protocol | In mode V the coordinator queries every regional neighbor of each uplink sender with w < 0.5. A neighbor replies with **its own border view** of the sender's region (burning cells and max spread in a band of `halo_width`=3 cells; `HierFireEnv.border_view`). Reply loss follows the neighbor's uplink state but uses a separate RNG and does not advance the Gilbert–Elliott state. A reply contradicts the report if the report claims fewer burning cells (−0.5) or lower max spread (−0.05) than the view; a strict majority of non-contradicting replies restores the report at weight 1. Compromised neighbors inflate the spread by ε. (Revision; previously replies were the sender's true report + noise.) | Uses only information a neighbor can observe. Sound for honest fresh senders (manuscript Prop. 2); cannot contradict overstated threat | `RiCoRSystem._apply_mode`, `Channel.verification_reply`, `HierFireEnv.border_view` |
| A13 | B | Deterministic evaluation policy | Greedy crew actions; drop allocation by largest-remainder rounding of the coordinator's probabilities | Avoids sending every drop to one region under argmax | `RiCoRSystem._self_greedy_drops` |
| A14 | C | Four-way diagnosis (clean, channel, corrupt, mislead) in Fig. 6 | Three-way: clean / channel / content, from p_ch < 0.5 then r̄ < 0.5 | The model has no head that separates corruption from misleading content | `evaluation/metrics.py::diagnosis_confusion` |
| A15 | B | Recovery-time computation for non-positive rewards | Moving average (window 10); recovered when the shifted reward reaches 95% of its pre-fault level | "95% of pre-fault" is ill-defined for negative rewards without a shift | `evaluation/metrics.py::recovery_time` |
| A16 | C | Dropout rate and noise of H-MAPPO+Drop | p = 0.2, Gaussian σ = 0.05 | Typical message-dropout setting | `configs/methods/h_mappo_drop.yaml` |
| A17 | C | ADMAC adaptation to the hierarchy | One joint reliability head (with metadata input) gating messages at both levels; no uncertainty, risk, modes, or shield | Captures "estimate each message's reliability and adjust its influence" without ADMAC's exact decomposable decision structure | `configs/methods/admac_h.yaml` |
| A18 | C | HPSF reimplementation details | GRU predictor fills stale or missing reports (trained by MSE on the true report); the one-step shield stands in for the predictive safety filter | The original code is not available | `configs/methods/hpsf.yaml`, `models.MissingInfoPredictor` |
| A19 | B | Which message set defines the "full" policy in Eq. 7 | Reference weights w0 = gate with κ = 0; ψ is the KL between that policy and the one with sender j removed | Eq. 7 needs gate weights to define π(·\|M) before ψ exists. Using the risk-free gate breaks the circularity | `RiCoRSystem.run_episodes`, `_sensitivity` |
| A20 | C | Operational meaning of modes S and F, and the outage measure | S/V: messages with w < 0.5 are replaced by that link's last trusted content at w = 0.5 (or dropped if none). F: peer messages masked, regional goals frozen at the fallback snapshot, coordinator re-applies its last allocation. Outage = consecutive steps with no uplink arrival | Direct reading of Sec. IV-B ("relies on its belief state", "last trusted goal", "conservative allocations") | `RiCoRSystem._apply_mode` |
| A21 | B | Treatment of downlink goals | Goals are lost or delayed by channel faults but neither content-corrupted nor gated | The threat model assumes an uncompromised coordinator | `Channel.transmit` |
| A22 | B | Which action PPO trains on when the shield intervenes | The policy's proposed (pre-shield) action | Keeps importance ratios well-defined. The shield acts as part of the environment | `RiCoRSystem.run_episodes` |
| A23 | B | Rollout and episode alignment | One PPO iteration = `n_envs` complete episodes (`rollout_length` = `episode_length`) | Avoids bootstrapping across episode boundaries for the channel GRU | `Trainer.train` |
| A24 | C | Credibility-network inputs | Message, change since the link's previous message, deviation from the median of the messages **the receiver itself currently holds** (revision; previously the coordinator's uplink median was used for every receiver), and the receiver's own report (zeros for the coordinator). The joint head adds metadata | Implements "consistency with local observation, temporal history, and corroborating messages" with receiver-local information only | `RiCoRSystem.cred_features`, `_receiver_median` |
| A25 | B | Gradient path of reliability heads; calibration procedure | Reliability heads are trained only by Eq. 12 (gates enter the policy as detached inputs). Temperatures are fitted by NLL grid search on validation maps under compound faults | Eq. 13 adds L_rel to the same objective; with detached gates the two are equivalent to separate updates | `Trainer._reliability_loss`, `Trainer.calibrate` |
| A26 | B | Statistical unit for bootstrap; multiple comparisons | The seed is the unit; Holm correction is added | The paper does not state the unit and applies no correction (see PROJECT_REPORT.md) | `evaluation/aggregate.py` |
| A27 | B | Channel label definitions | y_ch = 1 when the held message arrived this step with age ≤ 1; y_cr = 1 when its content is unaltered and not stale | The paper defines labels only as "injected-fault labels" | `Channel.transmit` |
| A28 | D | HCN environment (MPE-derived, 1 leader + 6 followers) | **Not implemented** | Observation, reward, and fault-application details are not given in the paper | — |
| A29 | D | Trained weights and results at the planned paper scale; the original simulator | Paper-scale study not run. The revised manuscript reports a reduced-budget study (`configs/experiments/revision.yaml`) | Compute (see reproducibility.md) | — |
| A30 | B | What a regional agent can see of a neighboring region | A band of `halo_width` = 3 cells along the shared border (what crews near the border can see) | Needed to define verification without global state | `EnvConfig.halo_width`, `HierFireEnv.border_view` |
| A31 | C | Beta-reputation baseline (requested by Reviewer 3) | Per-link Beta evidence with forgetting 0.95; an arrival is a positive outcome if its wind fields match the receiver's own (coordinator: median of held reports) within 0.05 and its threat fields changed by ≤ 0.2 since the previous message; gate with E[trust] in place of ρ_lower and κ = 0; no modes, no shield | Classical BRS/TRAVOS-style trust with outcomes judged only from observable consistency | `RiCoRSystem._reputation`, `configs/methods/beta_rep.yaml` |
| A32 | B | Reference bounds | `oracle_gate`: gate weight = true label (fresh and unaltered), shield, no modes (privileged by design). `no_comm`: all received reports and goals discarded, shield on | Bracket the value of reliability information | `configs/methods/oracle_gate.yaml`, `configs/methods/no_comm.yaml` |
| A33 | B | Delivery of the shared operating mode | The mode chosen from the coordinator's view is applied to all regions without loss | Idealization, stated in the manuscript (Sec. 4.5) | `RiCoRSystem.run_episodes` |
